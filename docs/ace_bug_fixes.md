# ACE 缺陷修复简述

本文记录 2026 年 11 月在 `CLCI_ACE_D2D_V2` 中合入的 ACE 修复及 s206 回归结果。修复涉及数据码型、缓存和目录更新、通道握手与异常处理。

## 已修复的问题

| 问题 | 触发条件与影响 | 修复方式 |
|---|---|---|
| 同地址跨拍位置读回误报 | 一个地址在 burst 写中是第 2 拍，随后从同一地址做单拍读。原数据公式将事务内拍号也算进期望值，A 可能把 B 返回的正确存储数据判错。 | 生成和校验都按实际物理行地址及数据配置取值。DV、UVM 检查器按同一规则计算期望，并继续核对 B 实际存储与读回的数据。 |
| 旧 snoop 决策覆盖主事务结果 | B 先发出 AC，又提前处理同地址写请求。旧 snoop 的状态更新可能把已被 WriteUnique 作废的行恢复为有效。紧邻的第二笔 snoop 也可能读到第一笔尚未提交的旧状态。 | B 等先发的 snoop 完成 CR、所需的 CD 和目录提交，才接收后续 AW/AR。A 等待 AW/AR 的 READY 时仍可处理先到的 AC，并在前一笔 snoop 更新提交后接收下一笔 AC。 |
| snoop miss 或 WU 误伤同槽其他行 | 不同地址可能映射到同一缓存槽。原 snoop miss 路径可能覆盖槽内原有 tag，WU 也可能只凭槽号作废其他行。 | snoop 提交校验更新使能和当前 tag。WU 在 A 的缓存和 B 的目录中，仅作废地址落在该次写入范围内的有效行。 |
| ReadOnce 覆盖已有脏行的数据 | 多拍 ReadOnce 经过已有 UD 脏行所在槽位时，原逻辑可能刷新数据快照，之后 CD 交回的就不是原脏行的数据。 | A 只在需要分配或保留缓存行的事务完成时提交快照。读最后一拍或写最后一拍先暂存数据，缓存更新随有效 ACK 执行。AC 握手时锁存该次 snoop 所需的 CD 数据。 |
| 超时后丢失事务归属 | AC 长时间等不到 READY，或 CR/CD 延迟时，B 原先可能退出等待。迟到的应答会失去对应请求。主事务已发响应但 ACK 缺失时，也需要继续占用在途状态。 | AC、CR、CD 分阶段计时，超时置位后保留在途 snoop。B 等到对应 RACK/WACK 才释放主事务，并对等待 ACK 计时。AW 和 AR 竞争时只接收一路。APB 清错须等相应路径空闲。 |
| 非法响应或 burst 边界未正确拦截 | 错误 BID 可能提前结束写事务，错误 RLAST 可能让未收完的读 burst 发出 RACK，跨 4 KB 的 burst 也可能被发出。 | 错误 BID/RID 置位并保留当前事务，等待正确响应 ID。RLAST 与预期拍数不符时锁存错误并禁止 RACK。跨 4 KB 的请求在 A 发出 AW/AR 前拦截并置 `err_rsp`。 |
| 部分写覆盖未使能字节 | B 原先以整拍 `WDATA` 写入并比较，导致 `WSTRB` 为零或只选中部分字节时，也可能改写未使能的字节或误报数据错误。 | B 按 `WSTRB` 更新并校验选中的字节。未使能的字节保留原值，全零掩码时不更新数据存储。 |

其中，按物理行地址生成数据、snoop miss 更新门控和先发 AC 的排序修复由 `e0a7e30` 引入。本轮在此基础上补齐缓存提交、超时、握手和异常边界处理。涉及 [公共码型函数](../ace/ace_funcs.svh)、[ACE Master](../ace/module_a.sv) 和 [ACE Slave/Home](../ace/module_b.sv)。

## s206 验证结果

| 验证 | 实测结果 |
|---|---|
| DV 单元回归 | 3 个子测试全部通过，覆盖连续 snoop、同槽不同 tag、异常 BID/RLAST、4 KB 拦截、AC/AW 停滞、迟到 CR/CD、缺失 WACK、AW/AR 竞争和写掩码。 |
| DV 真实 CLCI 回归 | 28/28 通过，包含 `dirty_readonce`、`data_alias`、六种数据模式和读写 burst 边界。 |
| UVM 真实 CLCI 回归 | 34/34 通过，两个数据定向修复用例均以 sequence 模式通过。33 个普通用例合并后命中功能计划 44/44 个 bin，ACE 基本块覆盖率为 437/493（88.64%）。错误注入用例单独通过。 |

UVM 批次为 `all_20261125_141305_91b078`，汇总文件位于 s206 的 `uvm/out/regression/all_20261125_141305_91b078/summary.txt`。验证范围为上述场景和本工程功能覆盖计划。历史复现过程见 [缓存与 snoop 排序审核](rtl_review.md) 和 [已发现问题与复现范围](KNOWN_ISSUES.md)。
