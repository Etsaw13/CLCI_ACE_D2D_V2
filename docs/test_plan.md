## 3. 每项测试的检查重点

### 3.1 APB

- 配置在 A/Home 未启动新任务时完成，首次运行前读回核对两侧模式和种子一致。
- 检查 CONTROL、DATA_CFG、A BASE、A BURST_CFG、B SNOOP_CFG 以及可读状态/计数。
- 目前 PREADY 固定为 1；测试驱动仍采用完整 SETUP/ACCESS 握手并设置超时。
- 对已定义只读寄存器的写操作应不改变其内容。当前 RTL 不对这种写访问报 PSLVERR，不能误设期望。
- 未定义地址在 ACCESS 阶段应报 PSLVERR；只在该负向访问期间将其识别为预期响应。
- 清错位是脉冲，读回 CONTROL 只反映 enable。
- 当前清错会清 A 的 TX/snoop、B 的写/读计数，但 B 的 snoop 计数只受复位清零；测试按分段基线核对，并在设计文档中明确这一差异，不假定所有计数同步清零。
- 动态改数据模式不属于普通测试；模式切换采用独立仿真，避免原存储和快照数据失配。

### 3.2 独立事务与数据预测

- 模型根据已完成的 APB 操作和真实请求接受事件推进，不能读取 DUT 私有发生器信号来决定下一笔期望。
- 暂停不重置模型；已接受但尚未发出 AW/AR 的内部工作也必须在恢复/排空时正确处理。
- 不沿用旧版 11 笔单拍循环，也不把所有新配置都硬编码成一张固定循环表。
- 独立实现六种数据模式和 PRBS 零种子规则，不调用 DUT 的 ace_funcs.svh。
- W 数据按起始地址、当前拍号和配置预测；检查 WSTRB 和 LAST。
- R 数据同时根据 B 的四槽带 tag 存储规则、已送达的 W/CD、当前地址和拍号预测。不能将 B 当成无限容量内存。
- 区分存储命中返回的数据和未命中生成的数据。A 的内部自检公式与真实存储数据发生冲突时应报告失败，不改期望掩盖。
- CD 关联对应 AC/CR，并对照该行的预期快照；不能只检查它碰巧符合某个生成公式。
- 验证 ID、LEN、SIZE、BURST、读写属性及有效的 RRESP/CRRESP 组合。
- DV 实现对应范围内的独立检查；UVM 使用完整的事务模型、队列和缓存行为关联。

### 3.3 双端匹配和最终对账

- 十种通道 AW/W/B/AR/R/AC/CR/CD/RACK/WACK 分别做源端与目的端数量、顺序和载荷匹配。
- 检查两端 VALID/READY 的确定性，有效载荷不含 X/Z，背压期间 VALID 与载荷保持。
- 写事务数 = AW = B = WACK；读事务数 = AR = RACK，均在排空后比较。
- W 数据拍数 = 所有 AWLEN+1 之和；R 数据拍数 = 所有 ARLEN+1 之和。
- B 不能早于对应写数据完成；RACK 不能早于主端收到最后一个 R；WACK 不能早于收到 B。
- AC 与 CR 一一关联；CR.DataTransfer=1 才建立 CD 返回义务，结束时必须归零。
- 单拍 CD 的 LAST 必须为 1。
- 普通测试全过程零非预期错误；最终通过 APB 读回状态与计数，再与监视器对账。
- 链路两侧 RX、command ready、TX ready 连续稳定八拍才启动；流量和收尾期间持续检查链路。
- A 停发后 Home 继续运行。所有队列、通道、待确认状态及需要清空的目录闭合后，连续静默 16 拍，再观察 32 拍。
- APB 错误清除等分段计数场景按各自起始基线与总事件数核对，不能直接拿清零后的计数与全程事件比较。

## 4. 参数与回归规模建议

- 普通 smoke 默认最少 64 笔主请求，DATA_MODE=0，BURST_BEATS=4，SNOOP_GAP=10。
- 六种模式为 PRBS31、固定字节、Sequence、Walking-1、PRBS23、PRBS10；每种模式独立仿真。
- 常规 burst 长度为 2/4/8/16；边界补充 3/5/255/256。
- 单拍测试 LEN=0。BURST_CFG 的 LEN=0 边界仅表示一拍，不将其认作真正多拍覆盖。
- 基准用例先完成普通模式；边界测试用各自明确的地址/长度组合。最大长度不直接加入无限制的混合自动轮转。
- AXI burst 不能跨 4 KB。16 字节一拍时，256 拍恰为 4 KB，必须从 4 KB 对齐地址开始；255 拍也要结合实际起始偏移检查。
- 长 burst 读会推进内部起始行索引。边界场景按独立模型安排每次实际起始地址或限定为首笔单项测试，不能只检查 BASE 配置是否对齐。
- 保留非法跨界检测，发现 DUT 发出非法范围应失败，不能为了长 burst 仿真结束而关闭检查。
- 压力测试建议 512 或 1024 笔，gap 候选 0/1/10/64/255；不会默认穷举所有参数笛卡尔积。
- 第一轮仅运行 DV smoke、UVM smoke；成功后再执行六模式、定向及长度边界回归。
- seed 保留用于未来控制序列随机选择；固定配置下改变 seed 不应被宣称为改变硬件发生器的序列。

## 5. 已确认的停发计数语义

已确认 TX_TARGET 表示最少请求数，并不是任意配置下都强制等于最终完成数。
原因是通过 APB 停发存在写入生效时间，停发前接受的任务仍须完成。

- 最终完成数必须等于实际接受并发出的请求数，不能有丢失或多完成。
- 停发写入生效后不允许再接受新内部工作；先前已经接受的工作可以随后发出 AW/AR 并完成。
- 监视器记录达到目标、发起停发、APB 写生效、最终排空几个时间点，解释额外完成事务。
- 对暂停恢复测试，检查暂停前后序列连续，并核对实际请求边界。
- 若用户要求所有场景精确 N 笔，需要额外设计提前停发策略并验证 APB/任务接受时序；不能仅在最终日志中截断计数。

## 6. 正常、负向和诊断结果

- 普通功能测试：预期零错误；任何数据、协议、超时或对账错误都 FAIL。
- 错误注入测试：指定错误必须出现并按约定锁存/清除；没报错也是 FAIL。非指定错误仍 FAIL。
- 当前源码关注点提供单独诊断场景：同一物理地址先处于 burst 中间拍，随后作为单拍或另一种 burst 拍位置读取，观察存储数据与 A 自检期望是否冲突。
- 诊断场景若发现真实矛盾，报告 DIAGNOSTIC_FAIL/待规格处理，不作为普通 PASS，也不默认为 XFAIL 计入通过率。
- 并行运行中的缓存目录竞争和 256 周期超时按真实失败定位，不改成分窗口运行规避。
- 1 GHz 时 256 个 ACE 周期为 256 ns；UVM 超时配置不会改变内部超时阈值。
- 任何 RTL 修复先给出定位证据并获得用户确认。

## 7. 功能覆盖率建议：保留四组，九个覆盖点

只保留接口行为、数据模式和六个已确认缓存行为，不扩展大量 FSM/交叉覆盖。
拟定 44 个命名 bin，需逐项完成可达性和采样条件核对，不能将候选目标描述为已覆盖。

| 组 | 覆盖点 | 候选 bin |
|---|---|---|
| Basic | 主事务类别 | SW、SR、BW、BR，共 4 |
| Basic | ACE 属性 | WU、WLU、RS、RU、RO，共 5 |
| Basic | 请求起始行 | 相对当前 BASE 的 L0/L1/L2/L3，共 4；不将 burst 每个 beat 都当成新请求 |
| Basic | 多拍 burst 长度 | 2、3、4、5..15、16..254、255、256，共 7；单拍不采入此点 |
| Coherence | snoop 类型 | RS、MI、CI、RO，共 4 |
| Coherence | CR 响应 | 0、8、16、24、21，共 5 |
| Coherence | R 响应标签 | plain、PassDirty、IsShared，共 3 |
| Data | 数据模式 | PRBS31、固定字节、Sequence、Walking-1、PRBS23、PRBS10，共 6 |
| Cache | 缓存行为 | 以下六项，共 6 |

六个缓存行为：

1. WU 完成后对应行作废。
2. WLU 完成后保留 UC，并具有正确数据快照。
3. RU + PassDirty 后行成为 UD。
4. RS + IsShared 后行成为 SC。
5. UC 行收到 RS snoop 后正确响应并降为 SC。
6. UD 行收到 CI 后返回正确 CR/CD，数据到达对端，行作废。

覆盖只在有效事务/握手及完整前后状态证据满足时命中。冲突期间无法可靠归属的观察记录为诊断，不能充当已命中。
Normal mixed 并不保证 WLU；由定向单拍写测试覆盖。并行下 RS 补读不必然得到 IsShared，由状态及真实响应判断。
纯 burst 测试不要求 snoop 覆盖。每项测试需满足自己的基本活动目标，整套回归再看覆盖并集。
用户关心的六种模式逐次运行，功能覆盖按相同计划版本/ACE 版本的逐 bin 命中做并集，不平均百分比。
默认合并通过的正常测试；错误注入和诊断结果另列，避免混淆正常场景证据。

## 8. 代码覆盖率与输出

- 两套环境分别保有自己的覆盖采集配置与报告工具，不互相引用。
- 只统计 module_a/module_b 对应实例；CLCI、TB、UVM 类不计入 ACE 代码覆盖率。
- 默认使用 VCS runtime 原生查询，保留 line、condition、toggle、FSM 状态和跳转的真实分子/分母。
- runtime 接口不支持的 branch 显示 N/A，不伪装为 0% 或 100%；原始 VDB 仍保存已采集数据。
- 两个互不重叠 ACE 实例可按分子/分母相加得到本次运行的合计；不同测试不能用汇总数重建代码点覆盖并集。
- 原始 coverage.vdb 分次保留；两套环境各自提供 `sim/merge_code_coverage.sh` 做原生位图并集和基本块源码查看，支持边界及目标验证状态见 [代码覆盖率说明](code_coverage.md)。默认运行不依赖 URG/Verdi。
- 控制台只打印一次功能汇总表、未覆盖项、代码覆盖表和明确的测试结论。
- 详细逐 bin 命中、错误关联、数据对账及原生查询明细保存到各自输出目录。
- 输出路径带测试、模式、长度、seed 和运行标识，重复运行不覆盖旧结果。
- 仿真结论与报告生成结论分别打印；要求的报告失败时脚本退出非零，同时明确仿真本身是否通过。

## 2026-10-22 定向补充
